# Language system

This document describes how languages work for players, DMs and builders, how the text appears on screen, and which scripts do the work. It describes the `language-nwnx` branch. The version deployed on the live server is the `dmfi-language-tables` branch; the differences are listed under "Branch status".

## Overview

A character speaks and understands a set of languages. Each language has a fluency level from 1 to 6. Level 6 is fluent: the listener reads the original text. Levels 1 to 5 read part of it. A listener with level 0 reads a scrambled imitation of the language.

The scrambled text is produced by substituting letters according to a fixed table per language. The speech itself is never encrypted; the original text is available to the scripts, which decide per listener what to show.

## Languages

| Id | Language | Learnable from books |
|---|---|---|
| 1 | Elven | yes |
| 2 | Gnome | yes |
| 3 | Halfling | yes |
| 4 | Dwarven | yes |
| 5 | Orc | yes |
| 6 | Goblin | yes |
| 7 | Draconic | yes |
| 8 | Animal | no (Ranger, Druid) |
| 9 | Thieves' Cant | no (Rogue) |
| 10 | Celestial | yes |
| 11 | Abyssal | yes |
| 12 | Infernal | yes |
| 13 | Drow | yes |
| 99 | Leetspeak | no (DM voice command) |
| 101 and up | rotating ciphers | no (DM voice command) |

Drow is signed rather than spoken (see "Drow sign language"). Languages 1 to 13 except 9 use a substitution table. `LangTable` in `dmfi_lang_inc.nss` holds one table per language: 52 slots of 4 characters, one slot for each letter in `a-zA-Z`, padded with spaces. A letter without an entry maps to itself. Thieves' Cant (`ProcessCant`) and the rotating ciphers (`ProcessCustom`) use their own code. A Thieves' Cant message is cut at 25 characters.

## Who knows a language

`LangFluency(oPC, iLang)` returns the fluency. It returns 6 when any of these is true:

- The character is a DM or DM-possessed.
- The character carries a `hlslang_<id>` widget or a `babelfish` item.
- The language is the racial default (`GetDefaultRacialLanguage`): Elf and Half-elf Elven, Gnome, Halfling, Dwarf, Orc and Half-orc Orc, Goblinoid Goblin, Reptilian and Dragon Draconic.
- The language is the class or subrace default (`GetDefaultClassLanguage`): Ranger and Druid Animal, Rogue Thieves' Cant, subrace "drow" Drow.

Otherwise the level comes from the character's learned-language list. The list is a local string `lang_known` on the character, for example `,4:3,10:2,` for Dwarven at 3 and Celestial at 2. An older entry without a level (`,4,`) counts as 6.

Local variables on a player character are saved in the character file. The following survive logout:

| Variable | Content |
|---|---|
| `lang_known` | learned languages and levels |
| `lang_slotsused` | language slots in use |
| `hls_MyLanguage`, `hls_MyLanguageName` | the language chosen for speaking |
| `lang_talk` | talk mode on or off |
| `lang_exp_<id>` | exposure points toward the next level |

## Learning a language

Languages are learned from books. Nothing else grants a language except a DM's `.teach` command.

### Books

Each learnable language has six volumes, item tag and resref `lang_book_<languageId>_<volume>` (66 items, generated by `tools/lang_books.py`). The player activates a book to study it (`lang_book_use`, called from `mod_activate`).

- Volume n raises fluency from n-1 to n. Volumes must be read in order.
- Reading a volume that gives a level the character already has does nothing.
- Volume 6 makes the character fluent.
- Books are not consumed.

### Language slots

A character may start a new language only while a slot is free. The slot total is the base Intelligence modifier (`(Intelligence - 10) / 2`, minimum 0, ability bonuses from items and spells are not counted). Volume 1 of a new language uses one slot. Volumes 2 to 6 of that language use none. Native languages never use slots.

Each use of a book reports the result and the remaining slots, for example "You study Goblin, volume 1 of 6. Volume 2 is next. You can start 2 more languages." A character with no free slot is told how many languages they know of the total allowed.

### The bookshelf

The `lang_bookshelf` placeable (`src/utp/lang_bookshelf.utp.json`) contains one copy of every book. Players may take books. The script `lang_shelf_fill` runs on the shelf's OnOpen and OnClosed events and adds any missing volume. The shelf has to be placed in an area in the toolset, because the build does not ship area `.git` files.

### Exposure

A character with a partial level (1 to 5) improves by listening. Each line heard in that language earns one exposure point, at most one per 30 seconds per language. A character at level n advances after n x n x 20 points. Reading a book sets the level directly and clears the stored exposure.

### DM teaching

`.teach <language> [1-6]` gives the language to the DMFI target at the stated level (default 6). It needs no slot.

## Speaking

Three input methods produce speech in a language. All three pass through the same logic.

### Typed `[text]` (voice script)

A message in square brackets, optionally with a `lang:` prefix, is spoken in the chosen language (`TranslateToLanguage` in `dmfi_voice_exe.nss`). A per-speaker buffer stops the same line from being processed twice within one second.

### The `.lang` window

`.lang` opens a window (`dmfi_lang_nui.nss`) containing:

- a pull-down of the languages the character knows,
- a text box and a Speak button,
- a log of lines the character understands,
- a status line with the current talk mode and the number of new languages the character can still start,
- two buttons: "Talk in this language" and "Talk normally".

Speak sends the text the same way a typed `[text]` does. Events go to `lang_nui_event`. Lines are added to the log by `lang_nui_append`, which `LangSpeak` runs with `ExecuteScript` so that the core include does not depend on the window code.

### Talk mode

`.speak <language>` chooses a language and turns talk mode on. Ordinary talk and whispers then come out in that language. `.speak off` returns to common speech. The setting is saved with the character.

Talk mode ignores shouts, party and DM chat, emotes (`*...*`), messages that begin with `.`, `[`, `:` or `/`, and DM characters.

### Range

| Volume | Range |
|---|---|
| Talk | 20 m |
| Whisper | 3 m |

A listener who is a player character needs line of sight to the speaker. A DM or DM-possessed creature hears every line in range.

## Drow sign language

Drow (id 13) is a sign language. The signer says nothing aloud, so there is no speech bubble and no scrambled text. Each viewer reads a description instead, according to their Drow fluency:

| Viewer | Text |
|---|---|
| Fluent (6) | The `<race>` signs, `<full text>` |
| Partial (1-5) | The `<race>` does not speak, but uses sign, you can only make out: `<known words>`. |
| No Drow | The `<race>` does not speak, but moves their hands and fingers in rapid patterns. |
| The signer | You sign, `<full text>` |

For a partial viewer, each word of the message is kept with a probability of 16% x fluency level. Punctuation is removed and lost words are left out without a mark, so only understood words appear, for example "danger challenge water". If no word is kept, the viewer reads "The `<race>` does not speak, but uses sign; you cannot make out any of it." Partial viewers gain exposure by watching.

`<race>` is the signer's race: Dwarf, Elf, Gnome, Halfling, Half-elf, Half-orc, Man, Goblin, Orc, Lizardfolk, Dragon, or Drow for a character with the subrace "drow". Any other race reads as "Creature". `LangRaceName` in `dmfi_lang_inc.nss` holds the list.

The same text rules apply in chat (typed `[text]`, the window, talk mode, NWNX) and in NPC dialog. The sign lines are also written to the `.lang` window log. An NPC signs when its local int `npc_language` is 13.

## Dialog variables

A dialog author can write `<race>` in any line of an NPC that uses `cond_lang_line`. The script replaces it with the NPC's race before the line is shown, in every language. For example, "The `<race>` looks you over." reads "The Dwarf looks you over." when the NPC is a dwarf.

## What the listener sees

`LangSpeak` (`dmfi_lang_inc.nss`) handles each listener in range.

| Listener | Chat log | Speech bubble |
|---|---|---|
| The speaker | `<name> says in <Language>: <original>` | original (NWNX) or scrambled (without NWNX) |
| Fluent (6) | `<name> says in <Language>: <original>` | as above |
| Partial (1-5) | `<name> says in <Language> (you catch only part): <garbled>` | as above |
| No knowledge | nothing, apart from a possible Lore notice | scrambled |

Garbling keeps each word with a probability of 16% x fluency level. Runs of lost words become one `...`.

A listener with no knowledge may see "`<name> is speaking in <Language>`" when `d20 + Lore rank` is above 20. The check runs at most once per 60 seconds per listener and language, and never for Thieves' Cant.

Every line a character understands also goes to the `.lang` window log, when that window is open. Lines the character does not understand are not logged.

### Without NWNX

The speech bubble can show only one text. `LangSpeak` makes the speaker say the scrambled text (`SpeakString`), and the readable translation arrives as a separate system message in the chat log. In talk mode (`LangHandleTalk`, called from `mod_chat`), the speaker's own chat line is replaced by the scrambled text through `SetPCChatMessage`.

### With NWNX Chat

When the NWNX Chat plugin is enabled, the module registers `lang_nwnx_chat` at load (`LangNwnxInit`, called from `mod_load`). For a player in talk mode, `dmfi_lang_nwnx.nss` cancels the original chat message (`NWNX_Chat_SkipMessage`) and sends one chat line per listener with `NWNX_Chat_SendMessage`. Each line is labelled `[Language]` and contains:

- the original text for the speaker and for fluent listeners,
- the garbled text for partial listeners,
- the scrambled text for everyone else.

Because these are real chat lines from the speaker, the speech bubble above the speaker's head shows what that listener understands. The window log receives a matching line. When NWNX is not active (`LangNwnxActive` is false), `mod_chat` uses the talk mode described above.

Setup: add `NWNX_CHAT_SKIP=no` to `config/nwserver.env`. The Chat plugin has not been tested on this server.

## Chat commands

| Command | Who | Effect |
|---|---|---|
| `.lang` | everyone | open the window |
| `.languages`, `.langs` | everyone | list known languages with levels, the language in use, talk mode, free slots |
| `.speak <language>` | everyone | choose the language and turn talk mode on |
| `.speak off` | everyone | talk mode off |
| `.learn` | everyone | prints a hint that languages come from books |
| `.teach <language> [1-6]` | DM | give the DMFI target a language, no slot needed |

`mod_chat` processes these. The same handler also runs the `.w` builder commands.

## NPC dialog

A dialog node cannot change its text per player. NPC lines in a language use a custom token as the node text (for example `<CUSTOM60000>`). Each link into the node carries the condition script `cond_lang_line` with two parameters, `token` and `text` (the original line). The script (`dmfi_lang_dialog.nss`) sets the token before the node is shown:

- Fluent speaker: the text as written.
- Partial speaker: `(Language) ` followed by the garbled text, with exposure gain.
- No knowledge: `(Language) ` followed by the scrambled text.

The NPC's language is its local int `npc_language` (a language id, or -1 for the common tongue). Without that variable, the NPC speaks its racial language, if it has one.

`tools/lang_dialog.py <file.dlg.json>` converts the NPC lines in a dialog. It skips a node that already has a condition script on a link into it and reports the node. Such a node needs a hand-written call to `LangDialogToken`.

Replies and branches use `cond_lang_know` with parameters `language`, `level` (default 1) and `not=1` to invert. Listing several NPC lines in descending level order, each with a different level, gives a branch per fluency band. The first line whose condition passes is shown.

The demo NPCs are Gruk the goblin (`lang_goblin`, dialog `lang_demo`) and Wren the archivist (`quest_wren`, dialog `quest_demo`, described in `docs/QUEST_DIALOG_EXAMPLE.md`). Both spawn beside the first plot giver in an area a player enters (`lang_demo_inc.nss`, called from `area_enter`).

## Branch status

- `dmfi-language-tables` (deployed, commit `9c1af98`): fluency 1 to 5, `.learn` grants a language, no books, no NWNX.
- `language-nwnx` (not deployed): fluency 1 to 6, books and bookshelf, NWNX Chat support, the quest dialog example.
