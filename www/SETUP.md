# UOA Development Environment Setup

This document is written so that an AI assistant can understand the full environment and help recreate it on a new machine. Read `CLAUDE.md` first for project context — this document covers only setup and tooling.

---

## What needs to run

There are three independent things:

1. **The website** — a PHP/MySQL site served by Apache (via XAMPP). Required to use the site normally.
2. **Playwright test suite** — JavaScript browser tests. Starts its own `php -S` server; does not need Apache or MySQL to produce partial results.
3. **Selenium test suite** — Python browser tests. Also starts its own `php -S` server; also works without MySQL (DB tests skip).

The test suites are the main concern for a fresh machine. The site itself is straightforward XAMPP.

---

## Platform notes

The project was developed on **macOS**. The only platform-specific hardcoding is the Chrome binary path in `selenium/conftest.py`:

```python
CHROME_BINARY = "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
```

On other platforms this must be changed before Selenium tests will run:

- **Windows:** `r"C:\Program Files\Google\Chrome\Application\chrome.exe"`
- **Linux:** `"/usr/bin/google-chrome"` or `"/usr/bin/chromium-browser"`

Everything else (PHP, Python, Node.js, MySQL) is cross-platform.

## Prerequisites

Install these before doing anything else.

### XAMPP

XAMPP bundles Apache, PHP 8.x, and MySQL in one installer.

- Download from https://www.apachefriends.org
- macOS: installs to `/Applications/XAMPP/`
- Windows: installs to `C:\xampp\`
- Start the XAMPP control panel and launch **Apache** and **MySQL**

**Critical:** `php` must be accessible from the terminal. XAMPP does not add PHP to PATH automatically.

macOS — add to `~/.zshrc` or `~/.bash_profile`:
```bash
export PATH="/Applications/XAMPP/xamppfiles/bin:$PATH"
```

Windows — add `C:\xampp\php` to the system PATH via System Properties → Environment Variables.

Verify:
```bash
php --version
# Should print: PHP 8.x.x ...
```

### Node.js (for Playwright)

- Version 18 or higher
- Download from https://nodejs.org or install via `nvm`
- Verify: `node --version` and `npm --version`

### Python (for Selenium)

- Version 3.11 or higher
- macOS: use the installer from https://python.org (the system Python is too old)
- Windows: installer from https://python.org; tick "Add Python to PATH"
- Verify: `python3 --version`

### Google Chrome

- Install the latest stable version from https://google.com/chrome
- `webdriver-manager` (used by the Selenium suite) downloads the matching ChromeDriver automatically — do not install ChromeDriver manually

## Configuration: uoa.php

Every PHP page that needs a database connection does `include('uoa.php')`. This file is intentionally excluded from git (credentials must not be committed).

Create it at the project root with these exact variable names:

```php
<?php
$host = '127.0.0.1';
$user = 'uoa';
$pass = 'FILL_IN';
$data = 'uoa';
$nwnport = "5121";
$dmlogin = "FILL_IN";
?>
```

- `$host` — always `127.0.0.1` (not `localhost`; the PHP code uses `mysqli_connect` which treats them differently)
- `$user` / `$pass` — MySQL credentials for the `uoa` database user
- `$data` — the database name (`uoa`)
- `$nwnport` — the NWN game server port; `5121` unless changed
- `$dmlogin` — the DM area password; used by the DM login form in `index.php`

## Database setup

The site uses MySQL with a single table. Run these in MySQL (phpMyAdmin works, or the XAMPP shell, or `mysql` CLI):

```sql
CREATE DATABASE uoa CHARACTER SET utf8 COLLATE utf8_general_ci;
CREATE USER 'uoa'@'127.0.0.1' IDENTIFIED BY 'FILL_IN';
GRANT ALL PRIVILEGES ON uoa.* TO 'uoa'@'127.0.0.1';
FLUSH PRIVILEGES;
```

### Table schema

The entire game state lives in one table:

```sql
CREATE TABLE pwdata (
    name VARCHAR(255) NOT NULL,
    val  TEXT,
    PRIMARY KEY (name)
) ENGINE=InnoDB DEFAULT CHARSET=utf8;
```

If you have a data dump, import it:
```bash
mysql -u uoa -p uoa < uoa_dump.sql
```

Without the dump, the site runs but shows no planets, players, or map data. The test suite handles this — DB-dependent tests skip automatically when MySQL is unreachable or the table is empty.

### How the DB probe works

Both test suites probe `galaxy.php?planet=infos` at session start. That page calls `die("service offline")` immediately when MySQL is unreachable. The test suites check for this string and skip DB-dependent tests if found. This means **the full suite runs without MySQL** — you just get 19 skips instead of 0.

## Playwright setup (JavaScript tests)

```bash
npm install
npx playwright install chromium
```

`npm install` reads `package.json` and installs `@playwright/test`.
`npx playwright install chromium` downloads the Playwright-managed Chromium binary.

### Config file: `playwright.config.js`

Key settings:
- `baseURL: 'http://localhost:8765'`
- `webServer`: starts `php -S localhost:8765` automatically before tests
- `waitUntil: 'domcontentloaded'` — used on all PHP page navigations because pages that call `die()` mid-render never fire the `load` event
- `screenshot: 'only-on-failure'`
- Browser: Chromium only

### Running Playwright

```bash
npm test                  # headless (CI mode)
npm run test:headed       # headed (watch it run)
npm run test:ui           # interactive UI mode
npm run test:report       # open last HTML report
```

Expected results without MySQL: **64 passed, 18 skipped**
Expected results with MySQL and data: all pass (DM login test also needs `UOA_DM_PASSWORD` env var)

### Playwright test files

## Selenium setup (Python tests)

```bash
pip3 install -r selenium/requirements.txt
```

### What gets installed

```
selenium>=4.26.0       # browser automation
pytest>=8.3.0          # test runner
pytest-html>=4.1.0     # HTML report with screenshot embedding
webdriver-manager>=4.0.0  # downloads the correct ChromeDriver automatically
```

### Why webdriver-manager

`webdriver-manager` downloads a ChromeDriver binary that matches the installed Chrome version and caches it in `~/.wdm/`. Without it, Selenium picks up whatever `chromedriver` is on `$PATH`, which is often stale (e.g. v139 when Chrome is v149) and causes `SessionNotCreatedException`.

Never install ChromeDriver manually — let `webdriver-manager` manage it.

### Config file: `selenium/pytest.ini`

```ini
[pytest]
testpaths = selenium
python_files = test_*.py
python_classes = Test*
python_functions = test_*
addopts = -v --tb=short --html=selenium/report/report.html
render_collapsed =
```

Key points:
- `testpaths = selenium` — pytest runs from the project root but only looks in `selenium/`
- `--html=selenium/report/report.html` — generates the HTML report
- No `--self-contained-html` — images are saved as separate files in `selenium/report/assets/`; keeps the HTML small (~108 KB vs 49 MB)
- `render_collapsed =` — empty value means nothing is collapsed; all screenshots visible immediately

### Config file: `selenium/conftest.py`

This is the most important file. It provides all shared fixtures and hooks:

| Item | What it does |
|---|---|
| `php_server` fixture (session) | Starts `php -S localhost:8766`; tears down after all tests |
| `db_available` fixture (session) | Probes `galaxy.php?planet=infos`; returns bool |
| `driver` fixture (function) | Creates a fresh Chrome WebDriver per test; quits on teardown unless `KEEP_OPEN=true` |
| `base_url` fixture (session) | Returns `http://localhost:8766` |
| `pytest_runtest_makereport` hook | After each test call: saves PNG to `selenium/screenshots/`, passes relative path to `extras.image()` so report embeds it |
| `_driver_stash_key` | `pytest.StashKey()` used to pass the live driver from the fixture into the hook without globals |

The screenshot hook uses `@pytest.hookimpl(hookwrapper=True, tryfirst=True)`. The `tryfirst=True` makes it the outermost wrapper so its "after yield" runs after pytest-html has already set `report.extras`, while the driver is still alive (fixture teardown is a separate phase).

### Running Selenium

```bash
# From the project root:
python3 -m pytest selenium/

# Headed (watch it run):
HEADLESS=false python3 -m pytest selenium/

# Leave browser windows open after each test:
KEEP_OPEN=true python3 -m pytest selenium/

# With DM login test:
UOA_DM_PASSWORD=<password> python3 -m pytest selenium/

# Single file:
python3 -m pytest selenium/test_index.py
```

Report opens at: `selenium/report/report.html`

## Known issues and fixes

### `SessionNotCreatedException: ChromeDriver version mismatch`

Cause: a stale system `chromedriver` binary (e.g. `/usr/local/bin/chromedriver`) is picked up before `webdriver-manager` runs.

Fix: `webdriver-manager` is already in `requirements.txt`. Make sure `pip3 install -r selenium/requirements.txt` completed successfully. The `_build_driver()` function in `conftest.py` explicitly passes `Service(ChromeDriverManager().install())`.

If the error persists, remove the stale binary: `sudo rm /usr/local/bin/chromedriver`

### `RuntimeError: PHP server did not start`

Cause: `php` is not on `$PATH`.

Fix: Add XAMPP's PHP binary directory to PATH (see Prerequisites above). Restart the terminal after editing the profile file.

### Screenshots show blank images in the report

Cause: The report was generated with `--self-contained-html` (a previous version of `pytest.ini`). That mode produces a 49 MB file and Chrome blocks `data:` URI navigation in new tabs.

Fix: Ensure `pytest.ini` does **not** have `--self-contained-html` in `addopts`. The current config is correct — if this was changed, revert it.

### Selenium form `action` attribute assertion fails

Cause: `element.get_attribute("action")` in Selenium returns the resolved absolute URL (`http://localhost:8766/index.php`), not the literal HTML attribute value (`index.php`).

Fix (already applied): all form action assertions use `.endswith("index.php")`, not `== "index.php"`.

### 19 tests always skip

This is expected. Those tests require MySQL to be running and the `pwdata` table to have data. They activate automatically once the DB is available. The DM login success test additionally requires `UOA_DM_PASSWORD` in the environment.

## Verifying the setup

Run this sequence to confirm everything works:

```bash
# 1. PHP in PATH
php --version

# 2. Node / npm
node --version && npm --version

# 3. Python
python3 --version

# 4. Install Node deps
npm install && npx playwright install chromium

# 5. Install Python deps
pip3 install -r selenium/requirements.txt

# 6. Run Playwright (no DB needed for baseline)
npm test
# Expected: 64 passed, 18 skipped

# 7. Run Selenium (no DB needed for baseline)
python3 -m pytest selenium/
# Expected: 70 passed, 19 skipped

# 8. Open the Selenium report
open selenium/report/report.html   # macOS
# or: start selenium/report/report.html  (Windows)
```

If steps 6 and 7 match the expected counts, the environment is fully working.
